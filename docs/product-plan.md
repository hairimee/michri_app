# mission_christ 기획안

> 선교사와 후원자를 잇는 **비공개 커뮤니티 앱**
> 문서 버전 v0.1 · 2026-08-11 · 작성 단계: MVP 정의

---

## 1. 문제 정의

선교사들은 지금 **네이버 밴드·카페·단톡방**으로 소식을 나눈다. 여기서 세 가지가 계속 걸린다.

1. **프라이버시가 없다.** 밴드·카페는 검색에 노출되거나 초대만 받으면 누구나 볼 수 있다. 사역지 사진 한 장, 지역명 한 줄이 선교사와 현지 사역자에게 위험이 된다.
2. **후원과 소식이 따로 논다.** 기도제목은 밴드에, 후원 계좌는 카톡에, 사진은 또 다른 곳에 흩어져 있다. 후원자는 "내가 후원하는 분이 지금 어떻게 지내는지"를 한곳에서 볼 수 없다.
3. **귀국 시 숙소 문제가 알음알음으로만 해결된다.** 안식년·보고 방문으로 귀국하면 머물 곳이 없다. 집이 없거나 비용을 감당하기 어려운 경우가 많은데, 숙소를 저렴하게 또는 무료로 내어주려는 사람은 분명 존재한다. 다만 서로를 찾을 방법이 인맥밖에 없다.

## 2. 우리가 만드는 것

**앱은 스토어에 공개되지만, 앱 안에 기록되는 모든 자료는 비공개다.**

이 한 문장이 제품 전체의 설계 원칙이다. 기도제목·사진·간증·후원 정보·숙소 주소 — 어느 것도 로그인하지 않은 사람에게는 보이지 않고, 웹에도 노출되지 않으며, 검색엔진에 잡히지 않는다.

## 3. 타깃 사용자

**대상 지역**: 필리핀·일본·동남아·국내 등 **SNS 사용이 가능한 지역**의 선교사.
보안 통제가 극심해 일반 SNS 자체를 쓸 수 없는 지역은 이번 범위가 아니다. 다만 그런 지역의 선교사가 안전한 곳에 나왔을 때 쓸 수 있도록, 가명·지역 비공개 옵션은 처음부터 넣는다.

| 페르소나 | 상황 | 앱에서 하는 일 |
|---|---|---|
| **선교사** (핵심) | 필리핀에서 사역 중, 후원교회 3곳·개인 후원자 20여 명 | 기도제목 올리기, 사역 사진 공유, 간증 나눔, 후원 계좌 안내, 귀국 시 숙소 요청 |
| **후원자** | 파송교회 성도, 매달 후원 중 | 소식 읽고 "기도했어요" 남기기, 후원 계좌 확인, 댓글로 격려 |
| **호스트** | 국내 거주, 빈방이나 사택이 있음 | 숙소 등록, 기간 설정, 요청 수락/거절, 특정 선교사에게만 열어주기 |
| **관리자** | 운영자(초기엔 haerim) | 선교사 인증 심사, 신고 처리, 강제 탈퇴 |

한 사람이 여러 역할을 겸한다. 선교사가 호스트일 수도 있고, 후원자가 호스트인 경우가 가장 흔할 것이다. **역할은 계정 종류가 아니라 프로필에 붙는 속성**으로 설계한다.

## 4. 범위

### MVP (v1.0)
- 회원가입·로그인, 프로필
- 선교사 인증(관리자 승인) 및 인증 뱃지
- 피드: 기도제목 / 간증 / 나눔 / 사진
- "기도했어요" 반응, 댓글
- 후원 정보: 계좌 안내 (앱 내 결제 없음)
- 숙소: 호스트 등록 → 게스트 요청 → 수락/거절
- 푸시 알림
- 신고·차단

### v1.0에서 빼는 것 (의도적으로)
- 앱 내 결제·정산 → 5절 참고
- 실시간 채팅 → 요청 메시지로 대체, 이후 검토
- 그룹/단체방 → 초기 사용자 수가 적을 때는 단일 피드가 낫다
- 웹 버전 → 프라이버시 원칙상 웹은 노출면만 늘린다. 앱 전용으로 간다
- 다국어 → 한국어만

## 5. 기능 명세

### 5.1 계정 · 온보딩

**가입은 열려 있고, 열람은 닫혀 있다.**

- 이메일 또는 카카오/애플 로그인
- 가입 즉시 접근 가능한 것: 자기 프로필, 앱 안내
- **로그인해야만** 피드·숙소·후원 정보가 보인다. 비로그인 상태에서 접근 가능한 서버 데이터는 없다

가입이 열려 있다는 건 신원이 확인되지 않은 사람도 들어온다는 뜻이다. 여기에 대한 장치를 세 겹으로 둔다.

1. **가입 시 최소 정보**: 출석 교회 또는 추천인을 적게 한다 (검증은 안 하지만 진입 마찰이 된다)
2. **인증 뱃지**: 선교사는 파송단체·추천인 확인 후 관리자가 인증을 부여한다. **인증 전에는 글을 쓰거나 숙소를 요청할 수 없고 읽기만 가능**하다
3. **신고·차단·강제 탈퇴**: 사용자가 신고하면 관리자에게 즉시 알림

> 후속 검토: 사용자가 늘면 "가입은 열되 피드는 인증자만" → "초대 코드제"로 조일 수 있게, 정책을 코드가 아니라 설정값으로 둔다.

### 5.2 피드

게시글 타입 네 가지. 작성 화면은 하나이고 타입만 고른다.

| 타입 | 성격 | 특징 |
|---|---|---|
| **기도제목** | 가장 자주 쓰임 | "기도했어요" 반응, 응답받은 제목은 '응답' 표시로 전환 |
| **간증** | 긴 글 | 응답된 기도와 연결 가능 |
| **나눔** | 일상·소식 | 짧은 글 + 사진 |
| **사진** | 사역 현장 | 여러 장, 캡션 |

**공개 범위**는 글마다 고른다: `전체 회원` / `내 후원자만` / `나만 보기`
기본값은 `전체 회원`이 아니라 **`내 후원자만`**으로 둔다. 안전한 쪽이 기본이어야 한다.

### 5.3 후원 — 계좌 안내 방식

**v1.0은 앱이 돈을 만지지 않는다.** 선교사가 후원 계좌를 등록하고, 후원자는 그 정보를 보고 직접 송금한다.

- 선교사 프로필에 계좌 등록 (은행·예금주·계좌번호, 후원 QR, 안내 문구)
- 후원자 화면: 계좌번호 **복사 버튼**, 지정 후원/일시 후원 안내
- 계좌번호는 **암호화 저장**하고, 인증된 회원에게만 노출
- 후원자가 "후원했어요"를 남기면 선교사에게 알림 (금액은 받지 않는다 — 자진 기록일 뿐)

**왜 앱 내 결제를 안 하는가**
사업자등록·PG 심사·기부금품법 검토가 필요하고, 애플·구글 인앱결제 정책과 수수료 문제가 걸린다. 무엇보다 이 셋을 정리하는 동안 정작 핵심인 커뮤니티가 못 나온다. **v2 로드맵에 남기되, MVP는 중개만 한다.**

### 5.4 숙소

이 앱의 차별점이자, 가장 조심해서 만들어야 할 기능이다.

**호스트 흐름**
1. 숙소 등록: 사진, 지역(시·구 단위), 수용 인원, 가능 기간, 비용(무료 / 실비 / 금액), 하우스 룰
2. 공개 범위 선택: `전체 회원에게 공개` / **`특정 선교사에게만`** (개인 집을 한 분을 위해 잠시 내어주는 경우)
3. 요청이 오면 수락·거절
4. 언제든 내리기 (등록·삭제는 호스트 권한)

**게스트(선교사) 흐름**
1. 지역·기간·인원으로 검색
2. 요청 보내기 (귀국 목적, 인원, 희망 기간, 메시지)
3. 수락되면 **그때 상세 주소와 연락처가 열린다**

**핵심 안전장치: 주소는 수락 전까지 마스킹한다.** 목록·상세에서는 "서울 은평구"까지만 보인다. 상세 주소·연락처는 호스트가 요청을 수락한 뒤에만 양쪽에 공개된다. 호스트의 집 주소가 회원 전체에게 열려 있어서는 안 된다.

### 5.5 알림

푸시로 보낼 것: 내 글에 달린 기도/댓글, 숙소 요청 도착, 요청 수락·거절, 후원 알림, 관리자 공지.
알림 내용에는 민감 정보를 넣지 않는다 (잠금화면에 사역지나 주소가 뜨면 안 된다).

### 5.6 신고 · 차단

모든 글·프로필에 신고. 차단하면 서로의 콘텐츠가 안 보인다. 신고 누적 시 관리자 알림.

## 6. 프라이버시 설계

제품의 약속이므로 별도 절로 둔다.

| 항목 | 방침 |
|---|---|
| **기본 거부** | DB는 Row Level Security로 전 테이블 기본 차단. 명시적으로 허용된 행만 읽힌다 |
| **비로그인 접근** | 없음. 공개 API 엔드포인트를 두지 않는다 |
| **이미지** | 비공개 스토리지 + 단기 만료 서명 URL. URL이 유출돼도 곧 만료된다 |
| **웹·검색 노출** | 웹 버전을 만들지 않는다. 크롤링 대상이 존재하지 않는다 |
| **위치·지역** | 사역 국가 표기는 선택. 가명 사용 가능. 위험지역은 "동아시아" 수준으로만 |
| **숙소 주소** | 요청 수락 전까지 시·구 단위 마스킹 |
| **후원 계좌** | 암호화 저장, 인증 회원에게만 노출 |
| **탈퇴** | 탈퇴 시 게시물·이미지 완전 삭제 (soft delete 후 30일 내 물리 삭제) |
| **스크린샷** | 기술적으로 막을 수 없다. 대신 가입 시 "캡처·외부 공유 금지" 서약을 받고, 위반 신고 시 강제 탈퇴 |

**솔직히 말해 둘 것**: 회원 가입이 열려 있는 한, 이 앱의 프라이버시는 "기술적으로 완벽"이 아니라 "노출면을 최소화하고 위반을 제재한다"에 가깝다. 정말 위험한 정보는 이 앱에도 올리지 않도록 온보딩에서 명확히 안내한다.

## 8. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 | **React Native + Expo** (TypeScript) | iOS/Android 한 코드베이스. Expo로 푸시·이미지·카메라가 바로 붙는다 |
| 라우팅 | Expo Router | 파일 기반, 딥링크 대응 |
| 백엔드 | **Supabase** (Postgres + Auth + Storage) | **RLS가 이 제품의 프라이버시 요구와 정확히 맞는다.** 정책을 DB에 박아두면 앱 실수로도 데이터가 새지 않는다 |
| 인증 | Supabase Auth (이메일 + 카카오 + Apple) | 애플 로그인은 iOS 심사 필수 |
| 스토리지 | Supabase Storage 비공개 버킷 + 서명 URL | |
| 푸시 | Expo Notifications | |
| 상태·데이터 | TanStack Query + Zustand | |
| 배포 | EAS Build / EAS Update | OTA 업데이트로 심사 없이 수정 가능 |
| 에러 추적 | Sentry | |

**대안 검토**: 백엔드를 직접 만들면(NestJS 등) 자유도는 높지만 인증·스토리지·권한을 전부 짜야 한다. 1인 개발에서 MVP까지 가는 속도가 압도적으로 다르므로 Supabase로 간다. 나중에 Postgres째로 들고 나올 수 있어 락인도 크지 않다.

## 11. 성공 지표

MVP 단계에서는 숫자보다 **"밴드를 대체했는가"**가 기준이다.

- 베타 선교사 중 **주 1회 이상 글을 올리는 비율** (목표 60%)
- 기도제목당 "기도했어요" 수 (목표 평균 5 이상)
- **숙소 매칭 성사 건수** — 이 앱만 할 수 있는 일. 베타 기간 중 1건이라도 성사되면 유의미
- 후원자 주간 재방문율

## 12. 리스크 · 미결 사항

| 리스크 | 대응 |
