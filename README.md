# mission_christ

선교사와 공동체를 위한 **초대제 프라이빗 커뮤니티 앱**.

파송교회·선교단체·기도모임처럼 우리만의 방을 만들고, 초대받은 사람끼리 기도제목과 사역 소식을 나눈다. 후원 계좌 안내와 귀국 시 숙소 찾기는 그 공동체 안에서 필요해지는 부가 기능이다. 지금 네이버 밴드·카페·단톡방에 흩어져 있는 일들을 한곳에서, 그리고 **훨씬 안전하게** 한다.

> **초대받은 커뮤니티의 멤버만 그 커뮤니티의 자료를 본다. 그리고 앱 바깥에는 아무것도 나가지 않는다.**
> 이것이 이 프로젝트의 설계 원칙이다.

**목적은 모금이 아니라 커뮤니티다.** 후원 랭킹이나 목표 게이지 같은 모금 장치는 넣지 않는다.

## 왜 만드는가

- **외부 노출**: 밴드·카페도 초대로 사람을 들이지만, 웹으로 열리고 설정에 따라 검색에 걸리고 링크가 밖으로 전달된다. 사역지 사진 한 장, 지역명 한 줄이 선교사와 현지 사역자에게 위험이 될 수 있다.
- **갈라진 채널**: 파송교회 밴드, 선교단체 단톡, 기도모임 카페 — 방마다 앱이 다르니 선교사는 같은 기도제목을 서너 번 복사해 올린다.
- **귀국 숙소**: 안식년·보고 방문으로 들어와도 머물 곳이 없다. 저렴하게 또는 무료로 방을 내어주려는 사람은 있는데, 서로를 찾을 방법이 인맥밖에 없다.

## 두 종류의 방

| | 누가 보는가 | 쓰임 |
|---|---|---|
| **프라이빗 커뮤니티** (기본) | 초대받은 멤버만 | 파송교회, 선교단체, 기도모임, 가족 |
| **열린 커뮤니티(광장)** | 앱 회원 전체 | 모두에게 열고 싶은 기도제목, 널리 알리고 싶은 후원 요청, 공지 |

어느 쪽이든 **앱 바깥(웹·검색엔진·비로그인)으로는 나가지 않는다.** 광장도 예외가 아니다.

## 주요 기능 (MVP)

| | |
|---|---|
| **커뮤니티** | 개설(회원 누구나) · 초대 링크/코드(만료·횟수 제한·즉시 무효화) · 멤버 관리 |
| **피드** | 기도제목 · 간증 · 나눔 · 사진. 작성 시 **올릴 방을 복수 선택** — 한 번 써서 여러 교회에 |
| **기도 반응** | "기도했어요" · 댓글. 방마다 따로 쌓인다. 응답받은 기도제목은 '응답'으로 전환 |
| **후원** | 선교사가 계좌·QR 등록 → 같은 방 멤버가 확인하고 직접 송금. **앱 내 결제는 하지 않는다** |
| **숙소** | 앱 전역 기능. 호스트가 방을 등록하고 **인증 선교사가** 요청. 전체 / 특정 커뮤니티 / **특정 선교사 지정**. 상세 주소는 수락 후에만 공개 |
| **가입** | **소속 교회 필수 입력.** 파송 선교사는 파송 교회도. 익명 가입 불가 |
| **인증** | 선교사는 관리자 승인 후 뱃지. 광장 글쓰기 · 후원 계좌 등록 · 숙소 요청의 조건 |

## 대상

필리핀·일본·동남아·국내 등 **SNS 사용이 가능한 지역**의 선교사와 그가 속한 공동체(파송교회·선교단체·기도모임), 그리고 숙소를 내어줄 수 있는 호스트.
보안 통제가 극심해 일반 SNS 자체를 쓸 수 없는 지역은 이번 범위가 아니다. 다만 가명·지역 비공개 옵션은 처음부터 제공한다.

## 기술 스택

- **앱** — React Native + Expo (TypeScript), Expo Router
- **백엔드** — Supabase (Postgres · Auth · Storage). 전 테이블 Row Level Security 기본 차단, **모든 권한 판정의 뿌리는 커뮤니티 멤버십**
- **이미지** — 비공개 버킷 + 단기 만료 서명 URL
- **푸시** — Expo Notifications
- **데이터** — TanStack Query + Zustand
- **배포** — EAS Build / EAS Update

웹 버전은 만들지 않는다. 크롤링 대상을 만들지 않기 위해서다.

## 개발 환경

### 준비물

- Node 20 이상, npm
- iOS 시뮬레이터(Xcode) 또는 Android 에뮬레이터, 혹은 실기기 + Expo Go
- Supabase 프로젝트 하나 (무료 티어로 충분하다)

### 앱 실행

```bash
npm install
cp .env.example .env      # Supabase URL과 anon key 채우기
npm start                 # i(iOS) / a(Android)
```

`.env` 에는 **anon key까지만** 둔다. service_role key는 RLS를 통째로 우회하므로 앱 어디에도 넣지 않는다.

### DB (Supabase)

마이그레이션은 `supabase/migrations/` 에 있다. 스키마 → RLS 정책 → Storage 순서로 세 개다.

```bash
npx supabase login
npx supabase link --project-ref <프로젝트-ref>
npm run db:push           # 마이그레이션 적용
npm run db:types          # src/types/database.ts 재생성
```

Docker가 있으면 `npx supabase start` 로 로컬 스택을 띄워 같은 마이그레이션을 먼저 시험해볼 수 있다.

### 명령

| | |
|---|---|
| `npm start` | Expo 개발 서버 |
| `npm run typecheck` | 타입 검사 |
| `npm run lint` | ESLint |
| `npm run db:push` | 마이그레이션 적용 |
| `npm run db:types` | DB 타입 생성 |
| `npm run test:rls` | 방 간 데이터 격리 회귀 테스트 |

### RLS 격리 테스트

`scripts/rls-isolation-test.mjs` 는 **커뮤니티 간 데이터 누출**을 회귀로 붙잡는다. 테스트 계정 3개로 로그인해 앱과 똑같은 경로(publishable key + 세션)로만 접근하므로, 여기서 막히면 실제 앱에서도 막힌다. 스키마나 정책을 건드렸으면 이걸 돌린다.

```bash
npm run test:rls
```

`.env` 의 `RLS_TEST_EMAIL_BASE` 주소로 플러스 별칭 계정을 만든다. 대시보드에서 Authentication → Email 의 **Confirm email 이 꺼져 있어야** 한다(개발 프로젝트 기준).

## 현재 상태

**M0 완료.** Expo 앱 골격(5탭)·디자인 토큰이 올라갔고, 마이그레이션 9개가 Supabase 프로젝트에 적용됐다. 방 간 격리 테스트 26개 전부 통과.

| 단계 | 내용 | 상태 |
|---|---|---|
| M0 | Expo + Supabase 세팅, 스키마·RLS | ✅ |
| M1 | 인증 · 프로필 · 선교사 인증 | |
| M2 | 커뮤니티 · 초대 · 광장 | |
| M3 | 피드 · 다중 방 게시 · 기도/댓글 | |
| M4 | 후원 계좌 | |
| M5 | 숙소 등록 · 요청 · 수락 | |
| M6 | 푸시 · 신고 · 차단 | |
| M7 | 클로즈드 베타 · 스토어 심사 | |

**남은 정리거리** — `supabase db advisors` 의 성능 경고 두 종류가 열려 있다. 정책 안의 `auth.uid()` 를 `(select auth.uid())` 로 감싸면 행마다가 아니라 질의마다 한 번만 평가된다(38건). 그리고 같은 동작에 정책이 둘씩 걸린 표가 8개 있다. 둘 다 피드 규모가 커지기 전에 한 번에 훑는 게 낫다.
대시보드에서는 Authentication → Password 의 유출 비밀번호 검사(HaveIBeenPwned)를 켜두면 좋다.
